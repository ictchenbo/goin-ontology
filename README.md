# Ontology OODA 决策平台 · v6

[实现依据] 本版本按 `docs/foundry-ontology-ooda-reproduction-plan-v2.html` 的首版交付范围实现 Ontology、OODA 和三个合成场景。文档中的“范围边界”仍按非目标处理。

## 运行

[代码依据] `docker-compose.yml` 定义 Node.js 后端、React 前端和 SQLite 数据卷；默认前端端口 18000、后端端口 3000。Linux 使用 `scripts/start.sh --build` 启动，使用 `scripts/stop.sh` 停止。端口冲突时先设置 `BACKEND_PORT` 和 `FRONTEND_PORT` 环境变量。

[代码依据] 首次空库启动默认注入三个场景的合成数据和演示账号。账号见 `README.md`；正式环境应设置独立的 `JWT_SECRET` 并更换演示账号密码。

## 已接入的功能

[代码依据] 模型工作台支持类型、属性、接口、链接、规则、函数、Action 和自动化配置；模型版本可预览迁移、发布并以新版本回滚历史定义。对象页提供检索、关系、证据、历史和受控附件。

[代码依据] 对象类型使用 `/ontology/types` 列表路由，支持名称、标识与分类搜索，以及 10/20/50 条每页的分页。列表可通过弹窗新建类型、编辑基本信息、发布初始草稿及删除；点击名称或“详情”进入 `/ontology/types/:typeKey`，在独立页面编辑属性、共享引用与模型版本。`/ontology` 仍可进入模型工作台的其他类别。

[代码依据] 关系 Link、Action、规则、函数、Interface 与自动化均使用 `/ontology/<module>` 的搜索分页列表，并以 `/ontology/<module>/<key>` 提供可直接访问的详情页。列表可编辑基本名称和说明、执行可用的删除或启停操作；完整定义、连接实例和试算仍在详情页。Action、规则和函数的列表基本信息保存会生成新定义版本。共享属性已提升为 `/ontology/shared` 独立列表，支持新建、编辑、查看版本与引用类型；对象类型详情保留引用及同步操作。

[代码依据] “对象类型与属性”先显示属性列表；添加与修改在弹窗中完成，列表可移除属性。列表改动需保存为类型新版本，再发布。共享属性库可创建和修改共享定义，类型可引用共享属性；共享定义更新不会自动改写已发布类型，需在对象类型详情的属性列表点击“同步”并发布新版本。修改已引用属性的本地副本会解除共享引用。

[代码依据] 决策工作台保存情境快照、证据引用、模型与规则版本、备选方案、隔离推演、硬约束与评分、决策理由、审批、执行、结果和回放 JSON。关键对象或证据变化会使旧批准失效。

[代码依据] 案例详情按“事实与快照 → 方案与评估 → 决策与审批 → 执行动作 → 结果与关闭”五个阶段展示。顶部提示当前阶段和下一步；点击阶段可查看对应操作与历史记录，AI 建议和情景推演位于可展开的辅助区域。布局设计见 `docs/case-workflow-layout-v1.md`。

[代码依据] “态势构建”在执行 Orient 后以表格展示快照中的相关对象、类型、角色和证据；对象标题可进入详情，无证据会明确标示。展示内容取自当前冻结快照，设计见 `docs/case-orient-object-evidence-table-v1.md`。

[代码依据] 态势构建同时展示触发事件的记录内容、对象之间的关系 DAG 图、适用触发规则的输入与命中结果，以及反证提示。关系图按 Orient 快照的对象与关系方向排列，对象可进入详情；窄屏可横向滚动。规则命中仅是核查提示；没有生成运行记录的风险指标会标为来源未记录。旧快照未冻结规则判断时需重新执行 Orient。公共安全演示对象使用具体名称加日期编号，原业务编号仍保留。设计见 `docs/orient-reasoning-trace-v1.md` 和 `docs/case-relationship-dag-v1.md`。

[代码依据] 决策区会标出未通过硬约束的方案和原因，并禁止选择。快照或备选方案变化后须重新评分；基于旧评分的决策记录作为历史显示，不能直接提交审批。修复说明见 `docs/case-infeasible-option-selection-v1.md`。

[代码依据] 案例退回方案阶段时旧审批自动失效；重新提交审批会替代历史待审申请，避免同一案例有多条可处理的待审记录。

[代码依据] 审批记录冻结所选方案的 Action 版本；定义变化会中断旧审批的执行并要求重新评分、审批。Action 运行记录保存执行时的定义和版本供历史回放。

[代码依据] 提交审批前会检查拟议 Action 的必填参数及类型。已批准的旧方案若缺少执行参数，案例详情会指出缺失字段；提案人可退回方案阶段，以原方案生成补全草稿，补齐后重新评分、记录决策并审批。执行时参数必须与获批方案一致。修复设计见 `docs/case-action-params-fix-v1.md`。

[代码依据] 案例触发对象、备选方案中的对象参数、独立 Action 执行与试算、对象 reference 属性和关系连接实例使用可搜索、可翻页的对象选择器；选择器显示对象标题和类型，提交时自动传递对象 ID。自动化规则执行时的触发对象 ID 由系统提供。交互说明见 `docs/object-parameter-picker-v1.md`。

[代码依据] 军事演训样板将经审批的行动方案关联到指令签发；指令回执由独立 Action 记录，并关联原指令。全部为合成训练数据。

[代码依据] CSV、JSON、人工表单和 Webhook 可进入来源区；Webhook 配置由 `WEBHOOK_SOURCES_JSON` 提供，格式为以来源键为索引的对象，每项包含 `secret` 和 `mapping`。请求须带 `X-Webhook-Secret` 与 `X-Delivery-Key`。重复投递键仅回放首次结果；同键不同内容返回冲突。

[代码依据] 附件默认保存在数据库同目录的 `attachments` 子目录，Docker 中位于 `/data/attachments`，单文件上限 10 MB。读取附件须拥有对应对象访问权限。

[代码依据] 外部动作副作用使用 Outbox。`OUTBOX_TARGETS_JSON` 将目标名映射到 HTTPS 地址；未配置目标会保持失败/待重试状态，不会被标记为已送达。目标服务应按发送的幂等键处理重复消息。

[代码依据] 可选 AI 适配器由 `AI_ADAPTER_URL`、`AI_ADAPTER_KEY` 配置。未配置时请求建议返回明确错误；配置后只保存候选解释、缺失事实或备选草案及自动检查与人工复核，不直接写正式对象。

## 验证、备份和恢复

[测试依据] `backend/npm test` 运行 22 项测试，其中共享属性测试覆盖复用、版本更新与历史类型定义冻结。HTTP 验收还覆盖导入到结果回放、Webhook 幂等、权限、演训指令与 AI 建议等路径。前后端使用各自的 `npm run build` 检查构建。

[代码依据] `scripts/backup.sh` 使用 SQLite 在线备份 API 导出数据库，并连同附件打包。`scripts/restore.sh <backup.tar.gz>` 会先备份当前数据，再停机恢复并重新启动服务。恢复前应确认端口环境变量与部署时一致。

[代码依据] `GET /api/health` 返回迁移计数和服务状态；`GET /healthz` 提供容器探活。SQLite 迁移位于 `backend/src/db/migrations/`，启动时自动顺序执行。

## 外部配置边界

[代码依据] 三个样板使用合成数据；外部仓储、物流、指挥链或 LLM 端点需由部署方提供并配置。未配置时，应用的内部决策流程仍可运行，Outbox 会记录未交付的外部消息。
