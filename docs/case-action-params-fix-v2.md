# 审批前补全方案动作参数 v2

## 问题

[数据库依据] 现有公共安全演示案例的“补充核实”方案包含 `ps_create_review_request`，但其 `params` 为 `{}`；Action 定义要求 `objectId` 和 `reason`。评分和记录决策可完成，提交审批才返回缺参错误。

## 设计

1. [设计方案] 在“决策与审批”读取所选方案的 Action 必填参数。缺失时显示字段名，禁用“提交审批”，提供“补全动作参数”入口。
2. [设计方案] 在补全表单中，以案例触发对象预填 `objectId`，由用户填写 `reason` 等其他必填值；用户保存前可核对参数。
3. [设计方案] 仅允许提案角色在方案阶段修改拟议动作的 `params`，保留原方案的名称、预测指标和约束字段。修改记录审计日志，并使旧评分与决策失效。
4. [设计方案] 保存后引导用户重新评分、记录决策，再提交审批。后端原有的审批参数和类型校验继续生效。

## 验收

- [验收目标] 旧案例的缺参方案在审批前显示 `objectId`、`reason`，且不能直接提交审批。
- [验收目标] 补全参数后旧评分失效；重新评分及记录决策后可以提交审批。
- [验收目标] 非提案角色、错误方案状态和无效参数请求不能修改方案。
