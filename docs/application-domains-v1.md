# 应用领域 v1

## 使用流程

1. 管理员在“应用领域”创建领域，并在详情页分配成员。
2. 用户登录后选择可访问的领域；切换领域时重新选择。
3. 客户端对领域内请求发送 `X-Domain-Id`。服务端验证领域状态和成员授权，并在写入本体、对象、来源、决策、Action、审计等记录时自动填写 `domain_id`。
4. 列表按当前领域过滤，按 ID 访问先检查资源归属。跨领域的对象、关系、证据和案例关联由数据库触发器拒绝。

## 现有数据与接口

- 迁移将现有数据归入 `dom_existing`；已有用户成为该领域成员。新建演示库时，种子用户也会加入初始领域。
- `/api/domains` 及其管理接口不要求选择领域；其他业务接口要求 `X-Domain-Id`。
- Webhook 配置可增加 `domainId` 指定目标领域，并在请求中发送相同的 `X-Domain-Id`。未设置 `domainId` 的旧配置仅能写入 `dom_existing`。
- 前端在浏览器会话中保存当前选择。权限以服务端实时校验为准，移除成员后原有选择立即失效。

## 当前范围

- 领域间没有共享本体定义或业务对象的入口。
- 首版保留旧表上的全局唯一技术键约束，例如对象类型 `type_key`、来源 `(source_key, external_key)`。不同领域创建这些资源时仍需使用不同技术键；后续如需领域内重名，须连同外键和历史版本表执行单独的数据迁移。
