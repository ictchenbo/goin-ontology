# 决策案例动作参数修复 v1

## 问题

旧案例的拟议动作可能将 `params` 保存为 `{}`。审批后，执行接口要求传入的动作及参数与已批准方案完全一致，因此执行时不能临时补填 `objectId`、`assignee` 等必需值。

## 处理流程

1. 提交审批前检查所选方案中每个 Action 的参数是否满足已发布 Action 的必填字段和类型。缺少参数时保留案例在方案阶段，并列出缺失字段。
2. 已批准但参数不完整的旧方案在执行阶段显示修复说明，不提供无效的执行按钮。提案角色可退回方案阶段；退回使旧审批失效。
3. 页面以原方案的指标和动作生成一份待补全的新方案草稿，自动填入案例触发对象 ID。用户补齐其他参数后新建方案，重新评分、记录决策并申请审批。
4. 执行阶段只展示方案中已批准的参数；不允许在此阶段更改参数。后端仍执行原有的动作及参数一致性校验。

## 验证

- 缺少必填参数的方案不能提交审批，错误包含字段名。
- 合法参数可提交审批并执行；已批准旧方案的修复入口不会修改旧审批或已保存方案。
- 退回后旧审批失效，新方案需重新评分和审批。
