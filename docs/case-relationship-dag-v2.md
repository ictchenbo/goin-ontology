# 案例关系 DAG 业务流程修订 v2

[需求依据] 用户指出 v1 将关系实例的存储方向直接画成流程方向，导致“事件 → 来源”“个案 → 最初事件”，与演示案例的实际阅读顺序相反。

## 流程语义

[需求依据] 公共安全演示应从“市民反映来源 → 疑似异常行为反映事件 → 公共安全个案 → 巡逻核查任务 → 巡逻记录来源 → 广场未见异常事件”阅读。风险指标是从最初事件提取的旁支，不构成异常已核实的结论。

[代码依据] `event_from_source`、`case_has_event`、`task_for_case`、`indicator_based_on_event` 是本体关系的存储方向。页面在公共安全案例中读取这些冻结关系及根对象身份，沿业务流程重新定向展示边；不修改原始关系实例。新增 `task_produces_source` 关系类型，将演示巡逻任务与巡逻记录明确连接。新种子与既有演示库都建立任务及连接。通用领域仍沿原始关系方向显示。

[设计目标] 公共安全图仅在对象和关系都出现在当前快照时展示流程边，不从同名对象推断连接。若旧快照缺少巡逻任务，明确提示“巡逻安排未记录”，不宣称派发已发生。重新执行 Orient 后，新快照呈现完整流程。历史快照不回写。

[设计目标] 关系标签采用“从来源提取事件”“形成个案”“安排巡逻核查”“形成巡逻记录”“从记录提取结果”等能说明流程含义的短语。图下说明箭头表示演示案例的业务顺序，规则命中与事实核实仍以规则判断和证据区为准。

[设计目标] 公共安全流程自上而下排列，风险指标作为旁支。其他领域继续使用原有的横向 DAG 布局。

## 验证标准

[验收目标] 新的公共安全 Orient 快照从 SRC-市民反映开始，依次到首次观察事件、公共安全个案、巡逻任务、SRC-巡逻记录、广场未见异常事件；风险指标作为首次事件的旁支。图中不存在原先“事件 → 来源”的反向箭头。其他领域保持既有关系图；后端验收测试和前端构建通过。
