# 对象参数选择交互设计 v1

## 目标与范围

需要引用对象实例的表单统一提供可搜索、可翻页的对象选择器，显示对象标题、类型和 ID，并提交所选实例的 ID。对象类型和领域由当前操作决定，搜索通过现有 `/objects` 接口完成，继承服务端权限与领域过滤。

覆盖新建案例的触发对象、案例备选方案的 Action 对象参数、独立 Action 执行与本体 Action 试算、对象实例的 reference 属性以及关系连接实例。自动化运行时自动注入的 `objectId` 不要求人工选择。

## 组件和数据流

- `ObjectPicker` 管理搜索词、分页、类型过滤与选中对象展示；已选对象不在当前结果页时仍能显示其标题。
- `ActionObjectParams` 根据 Action 参数 Schema 中的对象引用元数据、惯用的 `objectId` / `*ObjectId` 字段以及审批策略中的关联对象字段，渲染一个或多个 `ObjectPicker`。非对象参数仍由现有表单或 JSON 输入管理。
- 在案例方案阶段选择对象时，更新 `proposedActions[0].params`；提交审批与执行仍使用该方案保存的参数，不在审批后修改。
- Action 执行和试算阶段选择对象时，仅更新该表单的参数 JSON；选择案例、方案或审批记录不属于对象参数，保持原流程。

## 验证标准

1. 对象搜索支持当前领域下的类型过滤、关键词与分页，不受首次 200 条列表限制。
2. 多个对象参数可分别选择；切换 Action 后不会沿用上一 Action 的对象 ID。
3. 旧值能够显示标题与类型；清空选择会清除对应参数。
4. 案例获批后的动作参数仍只读，后端的参数一致性与审批校验保持生效。
