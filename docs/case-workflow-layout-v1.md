# 决策案例详情页流程布局设计 v1

## 目标

将案例详情从连续堆叠的功能卡片调整为按业务顺序浏览的五个阶段。当前阶段和下一步始终位于页面顶部，用户可切换查看其他阶段的历史信息。保留现有案例 API、角色权限和表单能力。

## 阶段与操作顺序

| 阶段 | 主要内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 事实与快照 | 关联对象、事实缺口、Orient 快照；AI 建议为可展开辅助项 | 完成观察和定向 |
| 2. 方案与评估 | 建立备选方案、可选推演、运行评分 | 至少三种方案、快照和可行评分 |
| 3. 决策与审批 | 记录方案及理由、提交审批、审批处理与记录 | 审批通过 |
| 4. 执行动作 | 展示已选方案的动作和参数、执行记录 | 执行完成 |
| 5. 结果与关闭 | 预期与实际、证据、复盘、关闭 | 案例关闭 |

状态条仍显示精确状态，但阶段导航用中文业务名称。状态发生变化时自动切换到对应阶段；用户也可查看其他阶段。单次只展示一个阶段的详细内容，减少无关表单干扰。
案例处于 `OptionsReady` 且形成事实有效的可行评分后，默认进入“决策与审批”阶段；尚未满足条件时停留在“方案与评估”。

## 引导与边界

- 顶部给出当前状态和下一步提示，并显示各阶段已完成、当前、待进行状态。
- 推演位于评分之前；AI 建议放在事实阶段的可展开区域，并明确为可选。
- 按钮遵循现有角色矩阵；非执行角色可查看阶段说明和已有结果。
- 旧审批记录若为 `pending` 但案例已不处于 `PendingApproval`，标明该记录不可继续处理，且不显示可执行的批准/驳回按钮。
- 案例从待审批或已批准退回方案阶段时，旧审批自动失效；重新提交审批时，历史待审申请由新申请替代。
- 保留各阶段已有历史数据、错误提示、刷新和回放导出功能。

## 验证标准

1. 新建、待审批、执行中和已完成案例打开时，默认显示正确阶段。
2. 阶段切换不触发写入，表单提交后按新状态自动定位。
3. 窄屏上阶段导航可换行，键盘可聚焦和操作。
4. 现有前后端构建通过，案例动作和权限不变。
